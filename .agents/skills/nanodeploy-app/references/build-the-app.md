## The stack, and what breaks without it

| Layer | Use | Not this, because |
|---|---|---|
| Frontend | Vite + React + TypeScript, built to `dist/` | Next.js, Nuxt, SvelteKit SSR: pages outside `/api/*` are static files, a page server never runs. |
| Backend | Hono on Node 24, bundled to one `server.js` by esbuild | Express adds a second framework; anything with native addons cannot run without `node_modules`. |
| Database | Postgres through Drizzle ORM (`postgres` driver) | Prisma needs a native engine; SQLite files and MongoDB do not exist here. |
| Auth | none in the app: the gateway's headers | NextAuth, Passport, JWT login, sessions: the gateway already did it. |
| Styling | `styles.css` (shared) + `theme.css` (per app) | Tailwind: the split between shared rhythm and per-app theme is the design system. |
| API calls | `api()` from `src/client.ts` | A bare `fetch` fails on the first call after a sleep. |

Add a package only with `npm install <name>` (it updates `package-lock.json`)
and only if it is pure JavaScript. Then run `npm run check`: doctor refuses
packages that cannot work here.

## The template, file by file

| File | What it is | You |
|---|---|---|
| `app.yaml` | The contract with the platform | **Edit**: name, slug, access, roles, env |
| `server/index.ts` | Hono app: error handler, routes, `serve()` | **Edit**: your routes; keep `onError` and `serve()` |
| `server/schema.ts` | Drizzle tables | **Replace** the `notes` table with yours |
| `server/db.ts` | Postgres client, pool `max: 3` | Keep as is |
| `server/auth.ts` | `tryGetUser`, `getUser`, `hasRole`, `requireRole` | Keep as is |
| `src/App.tsx` | The demo notes interface | **Replace** with your interface |
| `src/main.tsx` | Mounts React, imports `styles.css` then `theme.css` | Keep as is |
| `src/client.ts` | `api()`: JSON calls that survive the wake-up page | Keep as is; always use it |
| `src/identity.ts` | `getMe()`, `hasRole()`, `loginUrl()`, `logoutUrl` | Keep; use it in public apps |
| `src/analytics.ts` | `trackPage()` for client-side navigation | Keep; call it on route changes |
| `src/styles.css` | Shared rhythm: spacing, type scale, states, focus | **Never edit** |
| `src/theme.css` | The art direction | **Rewrite completely** |
| `index.html` | Page shell | **Edit**: `<title>`, `lang`, `color-scheme` |
| `migrations/` | Generated SQL | Generated by `npm run db:generate`; never written by hand |
| `scripts/zip.mjs` | Makes the two zip archives | Keep; run `npm run zip` |
| `scripts/doctor.mjs` | Checks the code against platform rules | Keep; run by `npm run check` |
| `scripts/deploy.mjs` | Uploads with a deploy key | Keep; run `npm run deploy` |
| `test/` | Tests run by `npm test` | Add tests for logic that matters |

Commands: `npm run check` (types, tests, build, doctor), `npm run zip`
(check, then both archives), `npm run deploy` (upload), `npm run db:generate`
(migration from the schema), `npm run dev` (local development).

## Step 4: app.yaml

Set at least `name`, `slug` and `access`. Keep `backend` and `database` unless
the app truly has no server or no data. Add every secret the server reads to
`env`. For a public app with a back office, add `roles` and `protect`. All
fields and examples: [manifest.md](manifest.md).

Also set `<title>` and `<html lang="...">` in `index.html` to the app's name
and the user's language.

## Step 6: the schema and its migration

Write the tables in `server/schema.ts`:

```typescript
import { boolean, index, integer, pgTable, serial, text, timestamp } from "drizzle-orm/pg-core";

export const lists = pgTable("lists", {
  id: serial("id").primaryKey(),
  ownerId: text("owner_id").notNull(),         // Remote-Sub of the person
  name: text("name").notNull(),
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
}, (t) => [index("lists_owner_idx").on(t.ownerId)]);

export const items = pgTable("items", {
  id: serial("id").primaryKey(),
  ownerId: text("owner_id").notNull(),
  listId: integer("list_id").notNull().references(() => lists.id, { onDelete: "cascade" }),
  title: text("title").notNull(),
  done: boolean("done").default(false).notNull(),
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
}, (t) => [index("items_owner_idx").on(t.ownerId)]);
```

Rules:

- Every table whose rows belong to a person has `ownerId`, indexed.
- Children of a parent use a foreign key with `onDelete: "cascade"`: one
  atomic delete instead of two statements the container could be stopped
  between.
- No `users` table. A per-person settings table is fine, keyed by `ownerId`.
- Timestamps with time zone, set by the database.

Then generate the migration:

```bash
npm run db:generate
```

It writes `migrations/0000_<name>.sql` (plus `migrations/meta/`). It needs no
database. Read the SQL it produced. Keep every generated file.

`drizzle-kit generate` asks a question and waits when it thinks a column or
table was **renamed**. An agent cannot answer it. Never rename: add the new
column, copy data in a later step, drop the old one later (see
[change-an-app.md](change-an-app.md)).

## Step 7: the API routes (copyable patterns)

Keep the template's `onError` handler and `serve()` call. Put every route
under `/api/`. Answer JSON. Each pattern below checks the user, validates the
input, bounds the query and filters on `ownerId`.

```typescript
import { and, count, desc, eq } from "drizzle-orm";
import { db } from "./db.js";
import { items } from "./schema.js";
import { tryGetUser } from "./auth.js";

const MAX_ITEMS_PER_PERSON = 5000;

// List: always filtered on the owner, always limited.
app.get("/api/items", async (c) => {
  const u = tryGetUser(c);
  if (!u) return c.json({ error: "sign in first" }, 401);
  const rows = await db.select().from(items)
    .where(eq(items.ownerId, u.id))
    .orderBy(desc(items.createdAt))
    .limit(200);
  return c.json(rows);
});

// Create: type-check and bound every field, cap rows per person.
app.post("/api/items", async (c) => {
  const u = tryGetUser(c);
  if (!u) return c.json({ error: "sign in first" }, 401);
  const body = await c.req.json<Record<string, unknown>>().catch(() => null);
  const title = typeof body?.title === "string" ? body.title.trim() : "";
  const listId = Number(body?.listId);
  if (!title) return c.json({ error: "the title is empty" }, 400);
  if (title.length > 200) return c.json({ error: "the title is longer than 200 characters" }, 400);
  if (!Number.isInteger(listId) || listId < 1) return c.json({ error: "choose a list" }, 400);
  const [{ n }] = await db.select({ n: count() }).from(items).where(eq(items.ownerId, u.id));
  if (n >= MAX_ITEMS_PER_PERSON) return c.json({ error: `you already have ${MAX_ITEMS_PER_PERSON} items` }, 409);
  const [row] = await db.insert(items).values({ ownerId: u.id, listId, title }).returning();
  return c.json(row, 201);
});

// Update: match id AND owner, or another account could change the row.
app.patch("/api/items/:id", async (c) => {
  const u = tryGetUser(c);
  if (!u) return c.json({ error: "sign in first" }, 401);
  const id = Number(c.req.param("id"));
  const body = await c.req.json<Record<string, unknown>>().catch(() => null);
  if (!Number.isInteger(id) || typeof body?.done !== "boolean") return c.json({ error: "invalid request" }, 400);
  const [row] = await db.update(items).set({ done: body.done })
    .where(and(eq(items.id, id), eq(items.ownerId, u.id)))
    .returning();
  if (!row) return c.json({ error: "this item does not exist" }, 404);
  return c.json(row);
});

// Delete: same double match; 204 with no body.
app.delete("/api/items/:id", async (c) => {
  const u = tryGetUser(c);
  if (!u) return c.json({ error: "sign in first" }, 401);
  const id = Number(c.req.param("id"));
  if (!Number.isInteger(id)) return c.json({ error: "invalid request" }, 400);
  const gone = await db.delete(items)
    .where(and(eq(items.id, id), eq(items.ownerId, u.id)))
    .returning({ id: items.id });
  if (!gone.length) return c.json({ error: "this item does not exist" }, 404);
  return c.body(null, 204);
});
```

A row that does not belong to the caller answers 404, never 403: do not
confirm that someone else's row exists.

Error messages are shown to people. Write them in the interface language,
saying what went wrong and what to do.

## Step 8: the interface

- Replace `src/App.tsx`. Use the classes from `styles.css` (`page`, `stack`,
  `stack-tight`, `stack-loose`, `row`, `spread`, `muted`, `caption`, `num`,
  `empty`, `error`, `waking`) and `<button data-primary>` for the main action.
- Call the API only through `api()`:

```typescript
import { api } from "./client";

const rows = await api<Item[]>("/api/items", undefined, { onWaking: () => setStatus("waking") });
const created = await api<Item>("/api/items", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ title, listId }),
});
await api<void>(`/api/items/${id}`, { method: "DELETE" });
```

- Write four states from the start: **loading**, **waking** (the backend is
  starting: say so, the first visit is slow), **empty** (invite the first
  action) and **error** (what happened, what to do). `App.tsx` in the template
  shows all four.
- Labels name what happens ("Add", not "Submit"), and one action keeps one
  word everywhere.
- Usable at 375 px wide, controls at least 44 px tall, visible keyboard focus,
  everything reachable by keyboard.

## Scale-to-zero rules

1. **No state in memory.** No module-level `let`, `Map`, cache, counter or
   session. The next request may run in a fresh process.
2. **No timers, no cron, no queue.** A stopped app runs nothing. Do the work
   when a request arrives (compute "what is due" from dates stored in the
   database). If a job truly must run on a schedule, say so, set
   `idle.warm: true` and tell the user the app then runs permanently (~40 MB).
3. **No websockets.** Poll every 5 to 30 seconds while the page is visible
   (`document.visibilityState === "visible"`), or use `EventSource` (SSE),
   which reconnects by itself.
4. **Start in under a second, with no env value.** No warm-up, no model
   loading, no migration, no external call at import time. Read
   `process.env.X` inside the route that needs it. doctor starts `server.js`
   to check this.
5. **Pool at `max: 3`.** Already set in `server/db.ts`.
6. **Write before answering.** The process can stop right after the response.
7. **Files only in `/data`.** See "Files and uploads".

## Users, roles and public apps

- `tryGetUser(c)` returns the user or `null`. Every route that needs a user
  answers 401 on `null`. Use it even in private apps: access can be switched
  to public in the dashboard, and a crash on a missing header is a 500.
- `user.id` is the `ownerId`. Never key data on email or name.
- **Public app run by a few people** (anyone reads and posts, a few moderate):
  declare `roles: [moderator]` and `protect: - { path: /api/admin/*, role: moderator }`
  in app.yaml, put moderation routes under `/api/admin/`, and call
  `requireRole(c, "moderator")` in each of them. Never build a password, an
  admin page with a secret URL, or a login form.
- In the interface of a public app, call `getMe()` from `src/identity.ts`
  once. Show a discreet "Sign in" link (`loginUrl()`) to anonymous visitors
  and the moderation controls only when `hasRole(me, "moderator")`. Hiding a
  button is comfort; the server check is the security.
- Public apps where visitors post without an account: store no owner, bound
  every field hard, and add a per-day cap in the database.

## Security rules

- Validate at the edge: type first, then length, for every field.
- Bound every list with `.limit()`, and cap rows per person.
- Never build SQL by concatenation; Drizzle parameterises. Raw SQL only with
  the `sql` template tag.
- Never render HTML from data: no `dangerouslySetInnerHTML`, no `innerHTML`.
- Never let a client value reach a `style` or a class name. Accept a key from
  a fixed list (`"red" | "green"`) and map it in the frontend.
- Never accept a user id, role or owner from the request body or URL.
- Update and delete match the row id **and** `ownerId`.
- Everything in `dist/` is public, even for a private app: no key, no secret,
  no `import.meta.env.SECRET` in the frontend.

## Calling external services

```typescript
app.post("/api/summary", async (c) => {
  const u = tryGetUser(c);
  if (!u) return c.json({ error: "sign in first" }, 401);
  const key = process.env.OPENAI_API_KEY;               // read here, not at import
  if (!key) return c.json({ error: "OPENAI_API_KEY is not set yet: add it in the app's Settings" }, 503);
  const res = await fetch("https://api.openai.com/v1/responses", {
    method: "POST",
    headers: { authorization: `Bearer ${key}`, "content-type": "application/json" },
    body: JSON.stringify({ /* ... */ }),
    signal: AbortSignal.timeout(25_000),                // the proxy cuts at 30 s
  });
  if (!res.ok) return c.json({ error: "the summary service did not answer" }, 502);
  return c.json(await res.json());
});
```

- Declare `OPENAI_API_KEY` in `env` in app.yaml.
- Use Node's `fetch`: it goes through the platform proxy on its own.
- Only public HTTPS (443) or HTTP (80) destinations. Email goes through an
  HTTPS email API, never SMTP.
- Tell the user which service receives which data.

## Files and uploads

- Write only under `/data` (persistent) or `/tmp` (16 MB, wiped).
- Caddy serves only `dist/`, so a stored file is served by an `/api` route
  that checks the owner, e.g. `GET /api/files/:id`.
- Keep metadata (owner, name, type, size, path) in a table; name files on
  disk with `crypto.randomUUID()`, never with the uploaded name.
- Bound the size before reading the body (`hono/body-limit`, e.g. 5 MB), and
  check the content type against a short allow-list.
- The container has 256 MB of memory: stream large files, never buffer them.
- Deleting the app deletes `/data`. Say so if the files matter.

## Patterns worth reusing

- **A view per URL with the hash.** List-then-detail screens need the phone's
  back button: read `location.hash`, listen to `hashchange`. Call
  `trackPage()` from `src/analytics.ts` after each change (not on the first
  render).
- **Optimistic writes on anything tapped.** Update the list at once, send the
  request, put it back if the server refuses. Re-sort with the server's rule.
- **Keep the focus after adding to a list.** People add several in a row.
- **Compute, do not schedule.** "Overdue" is `dueAt < now()` in a query, not a
  job that flips a flag.

## Running it locally

- `npm run check` is enough to deliver. It needs no database.
- `npm run dev` starts Vite on 5173 and the API on 3000, and needs a
  disposable Postgres in `DATABASE_URL`. Without identity headers the API
  answers 401; to test a route by hand, send them yourself:
  `curl -H "Remote-Sub: dev-user" http://localhost:3000/api/items`.
  Never add a bypass to the code for this.
- The full signed-in loop happens on a Nanodeploy instance (a local trial
  works: see the nanodeploy-setup skill).

## Things that look fine and break

| Looks fine | Breaks because | Do instead |
|---|---|---|
| `fetch("/api/items")` | First call after a sleep returns HTML | `api("/api/items")` |
| `const cache = new Map()` at module level | Lost at every sleep, never shared | Postgres |
| `setInterval(cleanup, 3600_000)` | Never runs while asleep | Clean up during requests |
| `const client = new OpenAI({ apiKey: process.env.KEY })` at import | Crashes at boot until the key is set | Create it inside the route |
| `app.get("/health")` | Not under `/api/`, never reached | `app.get("/api/health")` |
| Reading `./data.json` with `fs` | The image has only `server.js` | `import data from "./data.json"` |
| `bcrypt.hash(password)` | Native addon; and the gateway owns passwords | No passwords in the app |
| `nodemailer` with SMTP | Port 587 blocked | HTTPS email API with `fetch` |
| Editing `package.json` by hand | `npm ci` refuses a stale lockfile (Git builds fail) | `npm install <name>` |
| A Google Fonts `<link>` | Third-party call, refused by doctor | Self-hosted `.woff2` in `theme.css` |
